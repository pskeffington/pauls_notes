## Routing algorithm

1. Match the requested change to one workstream and select its controlling documents.
2. Read the task ID and upstream dependencies in [agent-tasking.md](agent-tasking.md).
3. Resolve the actual git branch/commit and status; do not infer completion from a dated document.
4. Classify data as synthetic, permitted public, controlled or unknown. Unknown is not authorized.
5. Execute the smallest allowed change, test its outputs, and report path-level evidence.
6. Reconcile the human navigation, machine discovery and task record together.

## Indexing contract for agent consumers

Machine sections are generated by [build_machine_index.py](../scripts/build_machine_index.py), then enriched by [enrich_machine_index.py](../scripts/enrich_machine_index.py). Preserve `path`, `section_id`, source line span and content SHA-256, and record an exact repository commit at ingestion. Do not treat thematic routing or citation-registry presence as evidence that a primary paper has been individually verified. Keep derived vector stores outside the tracked repository unless separately approved.

**Task registry:** [Machine-readable task queue](agent-tasks.json) and [validator](../scripts/check_agent_tasks.py) are implemented with CI evidence at the linked baseline in [agent tasking](agent-tasking.md). IDX-01 and IDX-02 are **verified within bounded index/agent-registry scope** by the [dated evidence record](agent-index-evidence-2026-10-30.md). This does not imply the draft PR is merged, semantic retrieval quality is established, or independent scientific review is complete.
